# LendLoop design system

This guide describes the current frontend. Resolve conflicts using the rendered route and the effective cascade. [app/globals.css](../app/globals.css) contains shared tokens, defaults and styles used across screens. Profile and My Activity reuse the shared Button with local size and shape overrides in [profile.module.css](../components/profile/profile.module.css) and [activity.module.css](../components/borrowing/activity.module.css). Profile shares handover field styles with Loan Detail. See [UI architecture](UI_ARCHITECTURE.md) for placement, data boundaries and verification commands.

## Design philosophy

LendLoop feels like a neighborhood shelf. Warm paper, ink text and compact labels give it the structure of a printed guide. Lime marks an invitation, selection or important step. Object photography gives the signed-in shelf its character. Visible item names, prices, relationships and next actions carry the transaction.

| Experience  | Visual hierarchy and density                                                                                                                                                                                                                                                                                                                             |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Marketing   | A full-bleed illustrated stage follows one drill through a six-chapter journey, from cupboard to neighbor and back, with the header laid over it. Large, closely tracked headlines and sparse copy lead into paper-colored benefits, discovery and catalog sections. Journal and For Communities use the same header, type and ruled editorial sections. |
| Marketplace | A shallow ink header frames warm paper pages. Explore has an editorial introduction, followed by a rounded search bar, a price/category/sort row and even photo grid. Detail, activity and Listing Studio use bordered white panels, short labels and clear actions. Profile uses an ink identity panel alongside the private details form.              |
| Admin       | A separate ink header and navigation frame task-oriented lists, count cards and native form controls. Smaller type and denser rows accommodate scanning and moderation. Keep admin navigation and controls scoped to operations.                                                                                                                         |

Use the same palette, text hierarchy and focus treatment across experiences. Match the density and composition to the task. A story chapter can spend a viewport on one idea. An Explore result or admin record should communicate its useful fields at a glance.

There is no theme switch, `.dark` token set or system dark-mode stylesheet.

## Typography

[Root layout](../app/layout.tsx) imports **Space Grotesk** and **DM Sans** through `next/font/google`, Latin subset, `display: swap`. Next serves the built font files locally. Chromium loaded variable faces with weight ranges **300–700** and **100–1000**, respectively. Heading rules use `var(--font-heading), sans-serif`. Body uses `var(--font-body), "Segoe UI", sans-serif`. **Georgia** is a system serif used for editorial italic accents and the two Explore shelf headings, plus the camera heading and the Studio review item title. There is no project monospace role or custom local font import. An Arial declaration exists for an editor heading's `small` child, with no matching current heading markup in Listing Studio. Clerk's appearance config sets colors and radius without specifying a separate font family.

## Layout and spacing

There is no custom spacing scale. The CSS uses recurring px increments with fluid gaps and widths for larger compositions.

| Layout rule       | Current values and application                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public containers | `.shell` uses a 1240px cap and 24px gutters. Gutters are 18px at ≤900px and 15px at ≤390px. The homepage story independently uses a minimum 24px horizontal inset.                                                                                                                                                                                                                                                               |
| Dashboard content | `.app-main` uses a 1280px cap with 32px side gutters and 44px top padding on desktop. The width becomes `min(100% - 40px, 840px)` at ≤900px, then `min(100% - 36px, 700px)` at ≤700px. At ≤600px use 16px side gutters and 28px top padding. Activity caps at 1120px, Studio at 1240px, loan at 1040px and Updates at 940px.                                                                                                     |
| Admin containers  | 1280px cap with 24px side gutters, a 190px sidebar and 42px gap. At ≤850px the main stack has 16px side gutters.                                                                                                                                                                                                                                                                                                                 |
| Page headers      | App kicker, h1 (10px above and 12px below in the shared rule) and a muted summary. Marketplace actions align to the side on desktop and fall below the heading at ≤700px. Explore and Activity reserve about 30px before the next region.                                                                                                                                                                                        |
| Small spacing     | Use the relevant composition's 6–10px label/icon gaps, 10–18px controls and filter gaps, 12–28px panel and card insets. Explore card text has 16px padding or 12px on narrow phones.                                                                                                                                                                                                                                             |
| Large spacing     | Explore's desktop grid has 24px row / 18px column gaps. Detail uses a fluid 32–64px column gap. Studio uses 36px. Marketing sections use 80–120px vertical bands, commonly 65–75px on phones.                                                                                                                                                                                                                                    |
| Shape and depth   | 1px `--line` borders on cards and rules, 2–3px for selected rules or focus outlines. Use grid for comparable cards, form columns and persistent two-column workspaces. Use flex for actions, labels, wrapping chips and narrow layouts where items move as a row. Keep horizontal scrolling local to category or admin navigation strips. Keep minimum widths shrinkable on grids, and keep fixed navigation clear of page actions.

## Images, icons and illustrations

- **User photos.** Preserve the subject and original composition in the photo data. Display the ordered storage URLs from the query. The first attached photo is the cover. Explore/My Listings crop into 5:4, ToolDetail into 3:2, Studio preview into 4:3, Studio photo tiles and desktop activity thumbnails into squares. The mobile request image uses a full-row 190px frame. Admin thumbnails use 56px squares, reduced to 48px in compact listing rows. Use container aspect ratios and `object-fit: cover` for these crops. Camera preview uses `contain`. No generated photo substitutions or presentation-time image editing.
- **Upload processing.** [prepareImage](../components/listings/image-processing.ts) accepts JPEG, PNG and WebP up to 5 MB, honors orientation where the browser supports it, preserves proportions up to a 1600px longest edge, and encodes JPEG at quality 0.84 over white. Keep this existing technical processing and the Convex registration pipeline. [next.config.ts](../next.config.ts) only sets `devIndicators: false`. There are no custom `next/image` domains or optimizer settings. Functional photo markup uses native `img`. ToolCard adds lazy loading and async decoding.
- **Fallbacks and demo imagery.** ToolCard, detail and empty states use neutral backgrounds and package icons. Studio shows placeholder text without a cover. `public/images/demo-rizvi/` contains explicitly synthetic seed photos also used by QA. `public/images/hero-neighborhood.jpg` exists in the tree, while the current hero uses the original [drill SVG](../components/story/drill.tsx).
- **Iconography.** Lucide handles navigation, actions, category illustrations and fallback objects. Typical inline icons are 16–20px, the ToolCard fallback is 42px with a light stroke, and public category tile icons are 46px with a 1.5 stroke. Use labels for icon-only controls and hide decorative icons when the surrounding label supplies the name.
- **Marketing illustration.** [SceneArt](../components/story/scene-art.tsx) draws six layers on a shared 1440×900 canvas: the cupboard, two apartment blocks joined by a lime thread, an illustrative listing on a phone, the handover between two hands (both closed grips share a foreground `scene-4` layer above the drill, while the receiving sleeve and open hand stay behind it), the finished shelf on paper, and the closing loop between flats 4B and 7A. Handover hands are flat Warm Paper silhouettes with an Ink outline, following the supplied hand reference. Keep the shape readable through its outer contour, without nails, palm lines, skin shading or individually outlined finger segments. Sleeves retain the Ink/Paper/Lime palette. One traveling SVG drill moves across them, and a paper journey tag stamps each chapter. Overlay chips size with `cqw` canvas units. The radius demonstration uses CSS buildings and rings with explicit fictional names. Keep the art separate from catalog data and preserve readable narrative copy.

## Accessibility

**Implemented**

- Homepage skip link, labeled navigation, semantic headings and natural anchor scrolling. Active destinations use `aria-current` and button groups expose `aria-pressed`.
- Native labels, inputs, selects, disclosures and dialogs where specified above. Named thumbnail, date, photo-edit and modal controls. Calendar reports reserved dates in its accessible labels as well as its visual state.
- Focus rings, native disabled semantics and text for loading, errors and outcomes. Explore result count and the calendar's month and reservation message use live regions.
- Common navigation, form and action targets are around 44–54px tall. Compact actions vary. Desktop hover effects are guarded by pointer capability in the primary action and photo rules.
- [Contrast test](../tests/contrast.test.ts) covers selected brand text pairs at a 4.5:1 ratio. This is coverage of those pairs only. The public browser suite checks reduced motion, keyboard activation and no-JavaScript narrative reading.

**Recommended future improvements**

- Validate focus contrast on every light surface and the small admin heading label on its ink header. Keep distinct focus and selected cues.
- Verify focus containment and restoration for CameraCapture, mobile gallery keyboard order versus visual order, and error announcement consistency across loaded admin states. In Studio, the validation message follows the preview in the DOM and can land below the mobile viewport after a submit attempt.
- Recheck compact day/photo/admin targets on physical devices. Continue using visible text with state colors. Audit assistive-technology behavior separately from Chromium automation.

## Design System Audit Findings

| Classification                 | Evidence and implication                                                                                                                                                                                                                                                                  |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Established pattern            | The UI shares ink, paper, lime and two variable fonts. Explore uses 4/3/2 columns with a consistent 5:4 cover frame. ToolCard is reused by My Listings.                                                                                                                                   |
| Intentional exception          | Explore Georgia titles, Profile's ink identity card, admin's dense record layout and the homepage-only cinematic stage each have a scoped purpose. Explore and My Listings deliberately present the same ToolCard markup in different shells.                                             |
| Inconsistency                  | Primary-action sizing varies across the CSS base (54px), shared Button (44px), compact admin record (38px minimum), and share-details action (42px). Photo controls are 34px and calendar days 38px minimum. A single documented global target size would misrepresent the current UI.    |
| Inconsistency                  | Error, success and warning palettes differ between forms, calendar, borrowing, loan and automation. Several local border values remain, including `#B6C0D1` on base text inputs and `#AEBCB8` on handover inputs. Follow the scoped styles until those roles are deliberately reconciled. |
| Inconsistency                  | Lime is the effective generic focus outline. Its contrast is about 1.24:1 against white and 1.11:1 against Warm Paper. Profile/loan fields and calendar summary use distinct focus treatments. The admin header label uses `--muted` on ink at about 2.26:1.                              |
| Inconsistency                  | Updates distinguishes “Delivered” from “Sent”, while the loan activity list currently renders either of those values as “Sent”. Loan event timestamps in its lifecycle timeline use browser-local formatting, while delivery times specify Kolkata.                                       |
| Recommended future improvement | Review overrides whose markup has retired. Trace live selectors before any cleanup. Check the legacy font declarations against actual rendered headings.                                                                                                                                  |
| Recommended future improvement | Verify live protected states, long user text, physical touch, additional browser engines, camera capture and the Clerk account popover on isolated accounts.                                                                                                                              |
